# 마케팅 메뉴 운영

마케팅 현황, 전시회 조사, 업체·연락처, 참가 이력, 영업관리, 자료·출처를 제공합니다. 업체 상세의 영업 기록에서 단계·사내 담당자·우선순위·다음 연락일·메모·상담 이력을 저장합니다. 이메일/전화 링크는 사용자의 앱을 열며 자동 발송하지 않습니다. 수신거부 업체는 연락 예정 집계에서 제외하고 연락 링크를 비활성화하며 업체 CSV의 연락처를 비웁니다.

## 데이터와 범위

2026-09-19 자료: 전시회 1,614행, 국내 업체 2,241개, 참가 기록 2,343건, 제조 근거 후보 538개. 상세 참가 자료는 15개 전시회·연도 조합에 한정됩니다. 전국 전수조사 또는 국내 공장 확인 결과가 아닙니다. 동시 개최 전시·연도별 행과 통합 통계를 구분해야 하며 미확인 값은 0이 아닙니다. 원문 출처와 통계 기준연도를 보존합니다.

## 재수집 자료 반영

`node scripts/import-marketing-research.mjs <조사자료 폴더>`

입력은 events_ready.json, workbook_companies.json, stats_final.json입니다. 생성 결과는 public/marketing/research.json에 저장되며 전체 조사 엑셀을 public/marketing/research-2025-2026.xlsx에 함께 갱신한 후 빌드/배포합니다. 자료 버전과 전시회 연결표는 스크립트에서 검토하세요. 이름과 홈페이지로 만든 안정 키를 사용하므로 행 순서 변경은 영업 기록을 옮기지 않습니다. 기업명/홈페이지 변경·합병은 담당자가 기존 키 연결을 검토해야 합니다. 기존 고객관리/전시목록으로 자동 병합하지 않습니다.

## 공유 영업 기록

Supabase SQL Editor에서 supabase/migrations/0008_marketing_sales.sql을 적용합니다. marketing_leads와 marketing_activities, 원자적 저장 함수 marketing_save_lead를 생성합니다. 기존 WMS의 anon/authenticated 공유 작업공간 접근 방식을 따르며 사용자별 비공개 권한이나 로그인은 추가하지 않습니다. 기존 테이블과 정책을 변경하지 않습니다.

revision 충돌 시 저장을 거부합니다. 오류가 나면 입력 내용을 보존하므로 복사해 둔 뒤 창을 닫고 영업 기록 새로고침 후 다시 편집하세요. 서버 연결 실패 시 저장과 연락처 CSV를 비활성화합니다. 활동은 최근 100건 표시하며 DB에서 이전 기록을 보존합니다. 저장된 영업 업체 목록은 1,000개씩 끝까지 조회합니다.

`npm run build`, `npm test`, `npx eslint src/features/marketing`. DB 저장·활동 원자성·충돌은 롤백 트랜잭션으로 검증합니다.
